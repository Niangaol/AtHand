# 校园助手：云端运行

顺手的校园功能现在运行在 Qoder Sites 云端：

```
浏览器 ──同源──> Sites Function ──Bearer PAT──> api.hduhelp.com
                     │
                 云端数据库（只存 PAT 与授权状态）
```

网页不接收 HDUHelp 密码，浏览器也拿不到 PAT。首次连接使用 HDUHelp 官方设备授权（RFC 8628），在 `neo.hduhelp.com` 确认设备与权限。

## 1. 连接

1. 网页「设置 → 账号与后端」连接云端后端（部署后地址会自动填好），用账号密码登录；没有账号先注册。首个注册账号会继承此前单账号模式下的账本、生活记录和校园授权。
2. 打开「校园」页，选择权限：
   - **全部功能**：74 项权限，包含报名、选座、群聊等写操作。
   - **先只读**：只申请读取权限，需要写操作时再补充授权。
3. 点「生成授权链接」，在新页面用 HDUHelp 账号确认。
4. 回到校园页，页面会自动轮询；成功后显示已连接、权限数量和到期时间。

断开连接会在服务端调用 `DELETE /hduhelp-neo/cli/tokens/current` 撤销 PAT，并清除云端保存的授权。

## 2. 能做什么

Function 内置 `hduhelp-cli 0.4.126` 的 199 个操作，覆盖 14 个域：

| 域 | 内容 |
| --- | --- |
| 教务 | 课表、今明课程、成绩/GPA、考试、学习通作业、选课、学籍、教室、校历 |
| 校园生活 | 校园卡余额/流水、宿舍电费与绑定、二课活动、天气、失物、就业、志愿活动 |
| 图书馆选座 | 空间分类、可约日期、实时空座、预约、取消、ICS 订阅 |
| 空课表 | 房间、收藏、成员、邀请、排班、口令组队 |
| 信息流 | 首页聚合信息流、课表 ICS 订阅 |
| 群聊 | 课程群、班级群、年级群、创建/合并/同步/退出 |
| 身份 | 本人身份、绑定状态、校区、会话、授权应用 |
| 研究生 | 成绩、学籍、导师 |
| 提醒与阳光长跑 | 跑步记录、达标要求、成绩概览、提醒订阅与渠道偏好 |
| 知识检索 | 知识检索、快速问答、筛选标签 |
| 社区动态 | 帖子、评论、点赞、收藏、关注、举报 |
| 校友传话 | 传话、黑名单、生日祝福 |
| 长期记忆 | Agent 长期记忆的增删改查 |
| 文件上传 | 上传签名与续签（返回直传地址，不经过 Function 传文件） |

校园页的「常用」标签提供高频操作；每个域标签列出该域全部操作；「全部」标签可搜索 199 个操作。操作面板按接口 schema 生成参数和请求体表单。

## 3. 写操作与风险

- `read` / `sensitive-read`：直接执行。
- `write`：必须勾选「我确认执行这次写操作」。
- `high-risk-write`：还要输入「确认执行」。

写操作会带 `Idempotency-Key`；服务端在真正发出请求前校验权限和确认标记，缺权限时返回 `missing_scope`，页面提供补充授权入口。

## 4. 安全边界

- PAT 只存在云端 `shunshou_docs` 的授权文档中，不返回浏览器、不写日志。
- 网页本身需要先登录账号，并通过 Qoder Sites 的站点访问控制。
- 账号密码使用 PBKDF2-SHA256 加盐保存；会话 7 天有效，服务端只保存令牌哈希。
- 每个账号的账本、生活记录、日历、采集样本和校园 PAT 相互隔离；同一浏览器切换账号时，不会自动把上一个账号的本机账本上传到新账号。
- 设备授权链接含一次性 `user_code`，不要转发给其他人。
- 写操作影响的是真实校园系统：报名、选座、群聊管理、门禁上报等请在确认前核对参数。
- 校园 AI 对话目前仍由电脑上的内置助手工具提供；云端校园页负责查询和操作，不把 PAT 交给模型。

## 5. 账号与会话

- 注册：账号 3–32 位（字母、数字、下划线、短横线或中文），密码至少 8 位。
- 登录：账号不区分大小写；会话 7 天有效，退出登录会在服务端删除会话。
- 旧版单站点口令已停用；第一个注册的账号会接管旧数据，后续账号从空白开始。
- 同一浏览器切换账号时，本机账本和生活记录仍属于上一个账号：账本会进入冲突状态，生活记录会提示来源变化；请先导出备份，再明确选择保留哪一份。

## 6. 同步课表和考试

校园页仍保留「课表与考试」同步：从云端课表/考试生成 `hdu:` 开头的课程规则和日程事件，不动手动、ICS 和手机日历。已消失的校园条目不会自动删除，只提示到日程页手动清理。

## 7. 常见错误

| 错误 | 意思 | 怎么办 |
| --- | --- | --- |
| `invalid_credentials` / `username_taken` | 账号或密码不对；账号已存在 | 重新登录或换一个账号 |
| `campus_not_connected` | 还没有完成 HDUHelp 授权 | 在校园页生成授权链接并确认 |
| `missing_scope` | 当前 PAT 缺少操作所需权限 | 按提示补充授权 |
| `confirmation_required` | 写操作没有确认 | 勾选确认；高风险操作输入「确认执行」 |
| `campus_pat_invalid` | PAT 被撤销或失效 | 断开后重新授权 |
| `upstream_timeout` / `upstream_unreachable` | 连不上 HDUHelp | 稍后重试 |
| `invalid_arguments` | 参数不符合 schema | 按表单提示修正 |

## 8. 验证

```bash
npm test
node --test tools/function-smoke.test.mjs
node tools/campus-live-check.mjs
```

`campus-live-check.mjs` 只调用公开接口，验证云端代理的路径、参数与鉴权格式。个人课表、成绩、校园卡等需要你在网页完成 HDUHelp 设备授权后再验证。
