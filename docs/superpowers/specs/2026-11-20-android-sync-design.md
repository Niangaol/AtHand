# 顺手 v0.3：安卓采集 + Sites 云端 + 网页编辑

> 设计稿 · 2026-11-20 · 交付截止 2026-11-30 18:00

## 1. 要解决什么

v0.2 的每一笔都要手动输入。v0.3 改为：**手机自动收取支付信息和日程，云端存一份账本，网页用来查看和修改。**

- 安卓：读支付宝/微信的支付通知，读手机日历里的课程与考试；本地排队，联网上传。
- 云端：Qoder Sites 的数据库 + 函数，单用户设备令牌，网页和手机共用同一份数据。
- 网页：部署到 Qoder Sites，保留现有六个页面，新增今日日程与同步状态；支出、工时、单位、时薪照旧可改。

## 2. 目标与非目标

**目标**
- 支付通知在 10 秒内进入本地队列，联网后自动上传，重复通知只记一次。
- 日历里今天和未来 14 天的课程、考试自动出现在网页“今天”页。
- 网页修改的记录，手机下次同步可见；手机新增的记录，网页刷新可见。
- 权限未授予、解析失败、离线时，都有明确状态，不伪造数据。
- 保持 v0.2 的边界：不代付款、不代提交、不存学校账号密码。

**不做**
- 短信、微信聊天/群消息、学校教务登录抓取、OCR、iOS、多用户、应用商店上架。
- 日程的手动编辑（日历来处仍是手机日历；网页只读展示）。
- 无令牌访问云端数据（网页不登录也能用本地示例，但看不到云端账本）。

## 3. 方案取舍

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A 通知监听 + 云端 | 安卓原生采集，Sites 存账本 | **采用**；唯一能满足“自动采集 + 网页双向修改” |
| B 手机导出、网页导入 | 无云端 | 网页改动回不到手机，仍是半手工 |
| C PWA 分享/账单导入 | 不装原生 App | 最快上线，但每次仍要手动导出 |

## 4. 架构

```
支付宝/微信通知 ──┐
                  ├─ 安卓 App（Kotlin）──本地队列──┐
手机日历事件 ─────┘  只解析、不改原通知            │ HTTPS + Bearer
                                                  ▼
                                      Qoder Sites Function
                                      /api/sync（鉴权 + LWW 合并）
                                                  │
                                      Qoder Sites 数据库
                                                  │
                                      React 网页（Sites 部署）
                                      本地缓存 + 待上传队列
```

- 云端是唯一的合并点；手机和网页都可以离线，恢复后各自推、拉。
- 网页没有令牌时退化为 v0.2 的本地示例模式，方便评委直接打开看。

## 5. 数据模型

沿用 `RecordEntry`，新增同步字段：`updatedAt`（ISO 时间）、`deletedAt`（软删除，可空）。金额仍是整数分。

| 表 | 关键字段 |
| --- | --- |
| records | id, type(work/expense), date, title, amount_cents, category, workplace_id, start_time, end_time, duration_minutes, hourly_rate_cents, source(demo/manual/notification), updated_at, deleted_at |
| workplaces | id, name, hourly_rate_cents, description, source, updated_at, deleted_at |
| schedules | id(日历事件+开始时间哈希), title, location, date, start_time, end_time, updated_at, deleted_at |
| settings | 单行：hourly_rate_cents, updated_at |

- 支付通知生成 `type=expense, source=notification`，分类用商户关键词猜，网页可改。
- 日历只取标题、地点、起止时间，不取参与人和描述。

## 6. 同步协议

`POST /api/sync`，请求头 `Authorization: Bearer <token>`；令牌错误一律 401，不返回任何数据。

```json
// 请求
{ "since": "2026-11-20T12:00:00Z",
  "ops": [ { "entity": "record", "kind": "upsert", "id": "…", "updatedAt": "…", "data": { } },
           { "entity": "record", "kind": "delete", "id": "…", "updatedAt": "…" } ] }

// 响应
{ "serverTime": "…", "records": [], "workplaces": [], "schedules": [], "settings": {} }
```

- 合并规则：逐条比较 `updatedAt`，新者胜；删除写 `deletedAt`，不物理删除，保证其他端能收到。
- 幂等：记录 id 由客户端生成（UUID 或通知哈希），重复上传不产生重复。
- 时钟：以客户端时间为准，单用户场景可接受；响应返回 `serverTime`，偏差超过 5 分钟在网页提示。
- 首次使用：云端为空且本地有记录时，询问是否上传一次，避免丢已有账目。

## 7. 安卓端

**权限**
- 通知使用权：系统设置里手动开启；App 内检测并引导，不能自行授予。**默认路径**。
- 读取日历：运行时权限；拒绝则只采集支付，日程区显示空态。
- 受限屏幕读取（无障碍）：**默认关闭**，仅在探针确认通知不含金额时提示开启。约束见 7.1。

**采集**
- 通知监听与无障碍都只允许 `com.eg.android.AlipayGphone`、`com.tencent.mm`（支付宝、微信）；无障碍在 XML 的 `packageNames` 里写死这两个包，系统层面就不会把其他应用的事件送来。
- 无障碍只在窗口状态/内容变化时读文本节点，且只匹配支付结果关键词（支付成功、付款成功、已支付、收款、退款）；跳过密码框、输入框，不调用截屏接口，不记录按键，不保存整屏文本。
- 两条通道共用同一指纹去重：金额 + 商户 + 5 分钟窗口，避免同一笔被通知和屏幕各记一次。
- 无障碍属于高敏感权限：设置页必须解释“为什么需要、会读什么、不会读什么”，可随时在本机设置里关闭；关闭后自动退回通知路径。
- 解析金额、收支方向、商户、通知时间；原文只在本地“待确认”里保存 7 天，上传的只有结构化字段。
- 去重键：`包名 + 标题 + 正文 + 分钟级时间` 的哈希；同一条通知重复回调只入库一次。
- 解析失败：进入“待确认”，可手动补金额/商户后上传；不猜测、不计入汇总。
- 收支语义：支付 → 支出；退款、转账、非工作收款**不自动记账**，只进待确认并标注原因，由用户在网页补记（v1 无“退款”类型，避免净剩口径混乱）。
- 样本采集：debug 版提供“通知样本”页，用户主动导出脱敏文本，用于补全解析规则；release 版移除。
- 任何原始通知文本只留在本机，最多 7 天，自动清理；上传的只有结构化字段。

**同步**
- 立即上传一次 + WorkManager 每 15 分钟重试；失败保留队列并显示原因。
- 日历对账：每次同步读取“今天至 +14 天”的滚动窗口，与云端比较；窗口内消失的事件推送软删除。权限被撤销时上报 `calendarAvailable:false`，云端将该设备的日程标记为不可用，网页显示“日历未连接”，不再展示为今日课程。
- 界面只有三块：权限与连接状态、待上传/待确认、最近同步记录。不做账本编辑（编辑在网页）。
- 令牌存 EncryptedSharedPreferences；服务器地址可改，便于本地联调。

**构建**
- Kotlin + Jetpack Compose，minSdk 26，compileSdk 35，Gradle 8.9（`D:\AndroidSdkTools`）。
- 输出 debug APK，用户侧载安装（需允许“安装未知应用”）。
- 无模拟器镜像：解析和合并逻辑用 JVM 单测；通知与日历权限必须在真机验证。

## 8. 网页端

- 部署到 Qoder Sites；保留现有六页与视觉。
- 新增 `syncClient`：本地提交后入队，在线时推送并拉取；冲突按第 6 节。
- “今天”页新增：今日课程/考试、同步状态（已同步/离线/待上传/令牌失效）。
- 设置页：填写同步令牌、手动同步、最后同步时间、清除本地缓存。
- 离线写入沿用现有 Web Locks + localStorage；恢复网络后自动补传。
- 没有令牌或云端不可用时继续本地记账，并明确标注“未同步”。

## 9. 云端

- Sites 项目 + 数据库迁移 + 一个 `/api/sync` 函数；令牌放 Sites Secret，函数内常量时间比较。
- 数据库只允许函数用服务端密钥访问；前端永远不直连数据库。
- 只存金额、商户、时间、分类、日程标题与地点；不存通知原文、账号、设备通讯录。
- 令牌轮换 v1 走 Sites 控制台：新建 Secret → 网页/手机填新令牌 → 删除旧值。不做第二个管理端点，减少暴露面；步骤写进设置页说明。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 支付通知文案随版本变化 | 解析器数据驱动，多格式样本单测；失败进待确认，不猜金额 |
| Sites 函数/数据库能力与设想不符 | 第一天先做最小连通验证（写入+读回），再铺界面 |
| 真机权限无法在电脑上代授 | 用户可连 USB 调试：adb 安装、`pm grant` 日历、`cmd notification allow_listener` 开启通知；无障碍仍建议由用户本人在系统设置里确认 |
| 无障碍权限过宽 | 包名白名单、只读支付结果文本、跳过输入框、不截屏、默认关闭、可随时撤销；不追求应用商店上架 |
| 通知不含金额 | 11/21 探针同时采集通知与屏幕文本；若通知缺金额，按第 13.6 条降级 |
| 两台设备同时离线修改同一条 | LWW；单用户，冲突少，界面显示最后修改时间 |
| 令牌泄露 | 只存 Secret；设置页可重置令牌并使旧令牌立即失效 |
| 10 天内做不完 | 顺序固定：云端连通 → 网页同步 → 支付采集 → 日历 → 真机打磨；任何一步超时先保演示闭环 |

## 11.1 与现有杭电助手的关系

`D:\AgentPrograms\wechat-bot` 是客户端，校园数据实际来自 `D:\AgentPrograms\HDU-Helper` 的 Web API（登录 cookie + CSRF，问答接口，课表路由在 live 模式需 HDUHelp CLI + PAT）。

- **v1 不接入**：它需要额外常驻服务、学校 PAT，且单并发/60 秒超时；放进 10 天会挤压支付采集。日程继续读系统日历。
- **第二阶段复用**：网页或云端函数把“今天有什么课/考试”转给 HDU-Helper，沿用它的 `state/warnings/is_demo` 透传，不在顺手里另存学校凭据。
- 任何演示数据都必须带 `is_demo` 标注，不能当成真实课表。

## 12. 验收

- 通知：同一条支付通知重复回调，只产生一笔；解析失败不产生金额。
- 同步：手机新增 → 网页 30 秒内可见；网页修改 → 手机下次同步可见。
- 离线：断网记账不丢；恢复后自动补传，重复上传不重复记账。
- 日历：授权后今天课程正确显示；撤销权限后不显示旧数据为“今日”。
- 安全：无令牌请求返回 401；数据库中不存在通知原文。

## 13. 由我决定、你可否决的默认

1. 日程网页只读，编辑回手机日历（少一套编辑界面，避免两处数据源打架）。
2. 安卓端不做账本编辑，只做采集、待确认和同步状态（与“网页展示和修改”一致）。
3. 同步采用逐条 LWW + 软删除，不做操作日志回放。
4. 云端不可用或无令牌时，网页保留本地记账，但明确显示“未同步”。
5. 退款、转账、非工作收款不自动入账，进待确认由用户补记；v1 不新增“退款”类型。
6. 若真机通知不含金额（被系统或应用脱敏），自动采集降级为“账单导入”作为主路径，通知只做提醒；这一判断在 11/21 探针后定。
7. 无障碍是“受限兜底”而非默认：包名白名单、只读支付结果、跳过密码/输入框、不截屏、默认关闭；探针证明通知足够时不启用。
8. 日程按系统日历读取（你确认课表在校园系统日程里）；网页只读，不在网页改日历。
