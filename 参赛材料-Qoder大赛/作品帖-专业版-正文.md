## 二、作品是什么

**给谁**：有兼职的在校大学生。
**在哪用**：下班回宿舍的路上、睡前十分钟、周末算账的时候。
**解决什么**：把「这周打了多久工、赚了多少、花了多少、还剩多少」从三个互不相通的地方（排班群、支付账单、手写备忘）收回到同一个页面。

| 用户真正想问的 | 顺手怎么回答 |
| --- | --- |
| 这周我打了多久工、赚了多少？ | 首页与周账单按「工时 × 时薪」自动算出本周兼职收入 |
| 这周花了多少、还剩多少？ | 六类支出汇总 + 本周净剩（收入 − 支出） |
| 买这件东西，相当于要上多久班？ | 金额与时薪的换算直接摆在账单旁边 |

边界同样明确：第一版**只做**「记工时 + 记支出 + 看周账单」这三件事，目标是 15 秒内记完、算得准、刷新不丢；预算与理财建议、账单自动识别、多人协作、多学校适配都不在这一版。

## 三、为什么做

起点是一次很具体的下班：周五晚上从奶茶店回宿舍，我想知道这周到底赚了多少，于是翻了三处——排班在微信群里、工时在脑子里、花销在支付软件的月度账单里。三处都能查到东西，却没有一处能回答「这周净剩多少」。

复盘下来，现有方案有三种失效方式：

1. **纯流水账**：只记支出，不认「兼职按小时算钱」这件事，收入永远是一笔笼统的「工资」；
2. **记账 App 太重**：一上来要求建预算、资产、多账本，维护成本高于收益，记三天就放弃；
3. **信息天然割裂**：课表在教务系统、排班在群里、消费在支付账单、截止日期靠自己记。

所以第一版的产品判断是：**先让「记一笔」足够便宜，再谈汇总与洞察**。我给自己定的验收标准很土，但都可验证：

- 记一笔不超过 15 秒；
- 每笔收入、支出与周汇总必须算对（跨午夜工时、两位小数金额）；
- 刷新页面数据不能丢；
- 导出的 CSV 用 Excel 打开不能乱码。

## 四、怎么用（5 步）

1. **打开站点** https://athand-qnvq63y722x.qoder.zone —— 若出现登录页，点「注册」创建账号（账号名自取，密码 8 位以上，云端服务地址已自动填好），或点「先随便看看」直接浏览示例账本。
2. **记工时**：左侧「记一笔」→「记工时」，选兼职单位（预置「校园奶茶店 / 周末家教」）、填日期与起止时间、时薪；页面实时显示「3.0 小时，预计收入 ¥60.00」，点「保存记录」。**保存后示例数据自动清除，只保留你的真实记录。**
3. **记支出**：「记支出」填金额、选分类（吃饭 / 交通 / 日用 / 娱乐 / 学习 / 其他），保存即可，目标 15 秒内完成一笔。
4. **看周账单**：「周账单」页给出本周兼职收入、生活支出、本周净剩，可按天展开明细，可翻上一周 / 下一周，也可只看收入或只看支出。
5. **配置与导出**：「单位管理」先把常用兼职单位和时薪存好，之后记工时不用重填；「设置」里可导出 CSV（Excel 打开不乱码）、清空数据。

> 账本按账号保存在站点的云端服务里，换设备登录同一账号即可看到；示例数据只用于让人一眼看懂账本长什么样，记下第一笔真实记录后会被清除。

## 五、用 Qoder 做出来的过程

整体规模：**10 次提交、96 个源文件、约 9,600 行代码（不含测试）、41 个测试文件共 215 项单元测试全部通过**，开发集中在 11 月 20 — 22 日三天。

分工原则一句话：**Qoder 负责「快」，我负责「不对」。**

### 5.1 我写需求，Qoder 起骨架

我先写了一份《顺手 · 需求文档（通俗精简版）》：产品给谁、第一版做什么、明确不做什么、怎样算做好了。把文档交给 Qoder，由它生成 React + Vite + TypeScript 工程、路由与左侧导航（首页 / 今天 / 记一笔 / 周账单 / 单位管理 / 月度汇总 / 设置）。

**我改的**：导航按「学习与节奏 / 钱与时间 / 校园与远方 / 数据与设置」四组重排；首页只回答「今天要做什么」，不做成堆砌数字的仪表盘。

### 5.2 记账闭环交给 Qoder，计算规则由我定

Qoder 实现了工时计算（跨午夜、扣除休息）、六个支出分类、周汇总与按天明细。它最初给出的是一版「什么都能填」的表单。

**我改的**：

- 表单只留必要字段，备注可选，默认值给好（当天日期、9:00–12:00、上次使用的单位）；
- 结束时间早于开始时间必须自动按「次日」处理；
- 金额统一两位小数，支出分类固定六类，不允许用户自定义。

### 5.3 数据归属，我加边界

账本从浏览器本地存储起步；Qoder 另外做了一套账号与同步机制（账号隔离、云端保存、同账号跨设备可见），以及本机同步网关（运行在本机的 Node 服务，不暴露到公网），方便把账本放在自己的电脑上。

**我改的**：同步接口拆成只读 / 可写两种令牌，只读令牌不能改账；页面上写清「数据存在哪里」，不做隐式上传；账号切换时给出「保留哪一份」的选择，而不是自动合并。

### 5.4 功能开始生长，我负责砍

在这个骨架上，Qoder 继续产出专注计时、日程、旅记、校园办事入口、生活服务（MCP）等模块。

**我砍掉的**：预算与理财建议、账单自动识别、多人协作与社交、多学校适配。理由只有一个——**第一版要让人敢每天打开，而不是功能列表好看**。

### 5.5 部署与复验（Qoder Sites）

用 Qoder Sites 打包 dist/ 并发布，访问策略设为**公开访问**；发布后用未登录状态的浏览器复验页面可达。

**我验的**：首页、记一笔、周账单三条主路径逐页点过；刷新后记录仍在；示例数据在第一次真实记录后自动清除；`npm run build` 与 215 项单元测试通过。

### 小结

> 需求边界、字段取舍、计算规则、数据边界与验收清单由我确定，Qoder 负责把每一条变成能运行的代码。这次协作里，我的时间主要花在「决定不做什么」和「逐条验收」上，而不是写页面。
