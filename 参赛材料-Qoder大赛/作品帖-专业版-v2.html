一句话说清：「顺手 AtHand」是一个面向在校兼职生的工时账本 Web 应用——把兼职排班与日常花销记进同一个账本，打开首页就能回答「这周打了多久工、赚了多少、花了多少、还剩多少」。

在线地址：https://athand-qnvq63y722x.qoder.zone

形态：Web 应用，响应式布局，PC 与手机浏览器均可直接打开；Qoder Sites 部署，公开访问，无需安装。

二、作品是什么

目标用户：在校期间有兼职的大学生——校内勤工助学、家教、实习、跑单等，排班按周变化，收入按次到手，日常支出碎片化。

要回答的三个问题：

  1. 这周打了多久工、赚了多少；
  2. 这周花了多少、还剩多少；
  3. 这笔花销相当于几小时的工时。

功能范围（v1）：

模块 已实现
记账工时 / 收入 / 支出三类记录；支出分六类（吃饭、交通、日用、娱乐、学习、其他）；金额以「分」为单位存储、按两位小数展示
工时录入选择兼职单位后自动带出时薪；填起止时间，支持跨午夜；实时预览「X 小时，预计收入 ¥Y」
计薪调整可手填计薪时长，用于扣除休息等不计薪时间
周视图自然周（周一起始、共 7 天）汇总工时、收入、支出与结余；可翻上一周 / 下一周、回到本周；按天查看明细
月视图按月汇总，与周口径一致
兼职单位名称与时薪管理；改时薪不追改历史记录；有关联工时的单位不可直接删除
数据导出CSV 导出（UTF-8 带 BOM，Excel 可直接打开），示例记录带出处列
附带模块课表、专注、旅记、校园服务——同一入口下的独立页面，不参与账本计算

明确不做：打卡计时、教务系统抓取、多币种、CSV 导入、跨账号共享账本。

三、为什么做

起因很具体：我自己的兼职收入和开销分散在支付账单、备忘录和 Excel 里。月末能看到的是一串支出流水，看不到「这周实际干了多少小时」，也算不出「这笔钱要干几小时」。

现有方案的失效点：

方案 能做什么 失效点
支付账单支出流水齐全只有支出，没有工时与收入；无法把支出折算成工时
Excel 手工表结构自由、公式灵活手机端记一笔太重；公式易错；跨设备同步靠手动
通用记账 App分类记账成熟记账与工时是两套账；兼职收入按次不按周；报表口径不可调

由此确定四条设计约束，同时作为验收标准：

  1. 记一笔在手机上三次操作内完成；
  2. 首页首屏直接给出本周工时、收入、支出、结余四个数字，不进入二级页；
  3. 金额统一以「分」为整数参与计算，展示两位小数，任何汇总不出现浮点误差；
  4. 数据归属用户：账本保存在自己的浏览器里，不默认上传云端。

四、怎么用（5 步）

  1. 打开 https://athand-qnvq63y722x.qoder.zone 。首次进入停在登录页，点「注册」：账号 3–32 位（字母、数字、下划线或中文），密码至少 8 位，服务地址在 Qoder Sites 部署下已自动填好；提交后进入首页。
  2. 建一个兼职单位：进入「单位」，填名称（例如 校园奶茶店）与时薪（元）。之后记工时直接选它，时薪自动带入。
  3. 记第一条工时：进入「记一笔」，选单位、填日期与起止时间；若结束时间在次日，勾选「结束时间在次日（跨午夜）」；预览行即时显示时长与预计收入。
  4. 记一笔支出：同页切到支出，选分类（吃饭、交通、日用、娱乐、学习、其他），填金额，保存。
  5. 每周核对一次：回首页看四个数字；进「账本」翻周、按天核明细；需要留档时到「设置」导出 CSV。
口径说明：周为自然周，周一起始；修改单位时薪只影响之后的新记录，历史记录保留当时的单价；记录的计薪时长可单独填写，用于扣除休息时间。

六段过程：

  1. 定范围：先落验收清单，再让 Qoder 写代码。v1 只保留「记得快、看得懂周」两件事，功能堆叠全部推后。
  2. 定数据模型：金额以整数「分」存储（amountCents、hourlyRateCents），时长以分钟存储（durationMinutes），日期用 YYYY-MM-DD 字符串，避免时区与浮点两类误差同时进来。
  3. 定计算规则：周区间函数以「周一起始、7 天」实现，并写测试固定边界（跨年周、月末跨月）；工时收入 = 计薪时长 × 时薪，计薪时长由起止时间推导，扣休息时手填覆盖。
  4. 定数据归属：账本存在浏览器本地，键名固定；写入前比对存储内容，若其他标签页已改动则拒绝覆盖并提示刷新（guardedSave）。可选连本机网关做多设备同步，同步失败或版本不一致时保留本机修改、由人选择保留哪一版，不做静默合并。
  5. 定取舍：不做打卡计时——兼职时长以排班为准，打卡会引入漏打与补打的口径争议；不做云端 AI 建议——没有可靠的当期数据支撑，反而削弱账本的确定性。
  6. 部署与复验：在 Qoder Sites 内完成构建与发布，拿到公开地址；随后逐页走查、手机竖屏核对、导出 CSV 到 Excel 验证中文与列顺序。

两个版本的任务分布：国内版负责部署与验收（任务「部署前后端到 qodersite」「上线新版」），国际版负责功能迭代（任务「需求文档简化」「测试自动记账功能」「完善旅行规划功能」）；工作区同一个 AtHand，两侧各自留有任务记录与 diff，图 5–图 9 即从中截取。

我改了它什么（三处关键调整）：

  • 金额运算从「元」改成「分」的整数运算，消除 0.1 + 0.2 这类误差；
  • 记录写入时固化时薪快照，单位改价不再污染历史账目；
  • 示例数据单独标 source=demo，导出 CSV 时带出处列，不与真实记录混在一列。
